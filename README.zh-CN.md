## 映射关系

```
MacBook = 一台 iPhone Duo
  ├─ 上盖（屏幕）= 一块面板：外屏(A面背板) + 内屏(你正在看的桌面)
  ├─ 下盖（键盘）= 另一块面板：一块屏 + 背板
  └─ 铰链        = MacBook 转轴，在屏幕与键盘之间 = 屏幕的下边缘
```

关键推论：**你的桌面本身就是那块内屏，不需要重绘。** macOS 自己在渲染它，
所以这个 App 是个**透明** overlay，只叠加折叠时内屏上该出现的东西。

铰链的位置是物理固定的，所以折叠方向只有一种：从屏幕下边缘往上扫。没有可切换的设置。

## 效果构成

合盖瞬间**冻结一张全屏截图**，然后在它上面做折叠该有的光学变化。
**没有任何扫入、缩放或位移** —— 一开始就是整屏。

| 层 | 内容 |
|---|---|
| 冻结截图 | ScreenCaptureKit 取**一帧**转成 CGImage 冻住（含窗口、正在播的视频），整屏铺满 |
| 模糊层 | 三选一（菜单 →「模糊效果」）：**镜头失焦**（默认，8 级预渲染模糊做空间梯度）/ **磨砂玻璃**（整屏均匀 + 奶白）/ **液态玻璃**（iOS 26，整屏材质 + 四边倒角）|
| 折痕 | 骑在铰链那条边的光带，`透明→白.14→黑.30→白.16→透明`，越合越亮 |
| haze | 内屏眩光，越合越强 |
| 收尾压暗 | `fold > 0.55` 之后才介入，最深 0.35 |

### 三种模糊效果

菜单栏 →「模糊效果」，存进 UserDefaults（`blurStyle`）。三种共用同一张冻结截图、同一批
8 级预渲染模糊，也共用同一套图层堆叠 —— 区别只在**贴哪套图、用什么 mask、额外叠什么**：

| | 长什么样 | 怎么做的 |
|---|---|---|
| 镜头失焦（默认）| 空间梯度虚化，离铰链越远越虚，铰链那头最清楚 | 8 级模糊 + 4 停靠点梯度 mask |
| 磨砂玻璃 | 整屏均匀糊掉，泛一层冷调奶白 | 同一批图，mask 两端同色；另加一层白 |
| 液态玻璃 | 整屏材质，画面更透更艳，四条屏幕边上有玻璃的厚度 | 贴提饱和过的那套图 + 四边倒角折射 |

后两种都是**整屏**的材质，没有任何位移或扫入 —— 玻璃是「盖在屏幕上」的一整块，
不是从某条边推过来的一块板。第一版做成了扫过去的板，读出来是位移动画，不是材质。

#### 材质的进度曲线：为什么是 `fold^1.35`

磨砂和液态玻璃的糊度都走 `pow(fold, materialRamp)`，指数 **1.35（缓入）**。

线性映射下开头十几度就糊到看不清了：感知上的糊度对半径是**饱和**的，过了约 20px
再加半径基本看不出区别，于是整段角度里只有前 15% 在动，后面全程一个样 —— 一点渐变感都没有。
缓入之后 99°→30° 全程都在变：80° 时几乎还是清楚的，60° 中等，40° 才开始糊透。

#### 三种效果必须一眼分得开

这不是审美问题。第一版三种在常用角度下读起来是同一个东西，实测逐带锐度差不到 20% ——
因为失焦模式在 `fold=0.45` 时铰链那头也只有 7px 半径，整屏本来就已经糊成一片。
所以后两种各自都得有失焦模式**给不出**的特征：

- 磨砂：26% 的冷调奶白。平均亮度从 97 抬到 129 —— 是「一块盖上去的材质」，不是「没对上焦」。
- 液态玻璃：提饱和（1.60）+ 微提亮（0.05）的板身，加上四条边的倒角折射。
  失焦和磨砂都只会让画面**更平**，只有玻璃会让它**更艳**，而且边上有厚度。

### 液态玻璃（iOS 26）

板身就是那 8 层，只是贴的图被 `Blur.glassSkins` 改过材质 —— 玻璃是把背景「吸」进材质里，
不是盖一层半透明白（盖白只会越叠越灰）。真正的身份特征全部长在**屏幕边**上，原地不动：

| | 内容 |
|---|---|
| 倒角折射 | 四条边各一条窄带（默认 4.5% 短边 ≈ 44pt），越贴边画面被挤压得越狠。玻璃的厚度就是从这里读出来的 |
| 铺开范围 | 板身比截图大一圈（每边 2.5%），超出的部分被窗口裁掉 |
| 边缘高光 | 贴边一条细亮线，冷白（`#D8F0FF`）往里转暖白（`#FFE8CD`）—— 色散 |
| 板面柔光 | 斜向的一层弱光，锚在屏幕上（光源不动）|

「液态」体现在**开合越快，倒角越厚（最多 1.3 倍）、高光越亮**，材质被拉扯的感觉。
速度是 `|d(fold)/dt|` 过一道 80ms 滤波拿到的，不滤会跟着采样抖。

#### 倒角的取样方向是反的

真实玻璃的倒角折射的是**界外**的内容。但这块玻璃就铺在屏幕上，屏幕外面没有画面可折射，
所以取样方向反过来 —— 把**里面**的画面往边上挤：

```
S(u) = w · u^0.45        u = 从屏幕边往里的深度（0…1，单位是带宽 w）
```

`u^0.45` 在 `u→0` 处斜率发散，正好是倒角贴边那一段的强压缩，到内端自然收成 1:1，
而且单调递增，画面不会翻转。分 4 段仿射逼近这条曲线：相邻两段在接缝处**取样点连续**
（只有导数跳变），所以硬边拼接看不出缝，不需要交叉淡化。

均匀压缩（一次仿射）试过，读出来是**拖影**不是玻璃 —— 仿射压缩到处都一样，
而倒角的位移本来就是非线性的。

#### 玻璃板要比截图大一圈

倒角是把画面**往边上挤**的，所以 1:1 铺的话最外圈会被挤出一条空边 —— 看着就像玻璃没铺满全屏。
`glassOverfill = 0.025` 把板身铺成比屏幕大一圈（每边 2.5%），挤掉的那部分正好由溢出的内容补上，
超出屏幕的部分被窗口裁掉。顺带这 5% 的整体放大本身也对：透过有厚度的玻璃看东西本来就会稍微放大。

同一个毛病还有另一半：折射带原本贴的是**清晰版截图**，等于屏幕最外圈套了一圈没上材质的锐利内容，
玻璃更显得铺不到边。现在折射带贴的也是玻璃图，只是取比板身**浅几级**的那一张
（`rimIdx = amount x 8 x 0.25`）—— 全糊了就看不出画面被挤压，折射也就白做了；
和板身同级或更糊都不行，得比板身锐、又确实是材质。

#### 为什么不用 contentsRect

把源区域塞进目标带子，直觉是改 `contentsRect`。但那个的 y 轴原点在 macOS 上有歧义
（跟着 `contentsAreFlipped()` 走），调起来全靠试。改成直接算 frame：把整张截图缩放定位，
让屏幕上的 src 区域正好落到 dst 区域，再用父层 `masksToBounds` 裁掉多的部分 ——
纯几何，没有歧义，也顺带省掉一层 mask。

### 自拍验证

```bash
open -n --env MACDUO_SHOOT=/tmp/shots build/MacDuo.app
```

往 Stage 里灌一张**合成桌面**（不是真桌面），三种效果各渲几张，用 ScreenCaptureKit
只抓自己那一个窗口存 PNG，然后退出。

绕这么大圈是因为别的路都断了：`CALayer.render(in:)` 不支持 mask；`CARenderer` 在这台机器上
渲出来全 0；`CGWindowListCreateImage` 已经从 SDK 里撤了。而这套效果的正确性**全在 mask 和
嵌套裁剪上**，拿 CoreGraphics 复刻一遍合成只能验自己的算法，验不了 Core Animation 的真实行为。
`SCContentFilter(desktopIndependentWindow:)` 抓的是窗口服务器合成完的结果，和眼睛看到的一致。

抓自己的窗口用的是 App 自己那份录屏授权，所以**必须走 LaunchServices 启动**（`open`），
直接跑 `Contents/MacOS/MacDuo` 拿不到授权（`preflight = false`）。另外别把它塞进 `Task {}`
就完事 —— `layout()` 里的 `window.setFrame` 只能在主线程跑，而 nonisolated 的 `async` 方法
会被调度到后台执行器上，要显式 `@MainActor`。

靠它抓出来的东西：折射带均匀压缩读作拖影（改成分段非线性）、高光是一条宽白雾（收成细亮线）、
三种效果在常用角度下互相撞脸、以及材质的进度全挤在开头十几度里。

配套的两把尺子在 `/tmp` 的验证脚本里：逐带锐度和平均亮度。**逐带锐度只在同一带跨图比较时有效**，
而且合成桌面上大片纯色会让它反过来（糊图处处有小梯度，清晰图大多是 0），最后还是得看图。

### 过渡区间

默认 **99° 开始虚化 → 30° 虚化到最深**，30° 以下保持最深。线性映射到 `fold` 0→1。
两头都能在菜单里改：「把当前角度设为起始角 / 结束角」，或「恢复默认 99° → 30°」，
改完存进 UserDefaults。

### 为什么不是清晰图和模糊图做交叉淡化

第一版用两张图（清晰 + 最强模糊）调 alpha 叠加。这样眼睛会**同时看到锐利边缘和
模糊光晕**，读出来是重影 / 蒙纱，不是失焦 —— 真正的失焦必须是**半径本身连续增大**。

现在预渲染 **8 级**半径线性递增的模糊图堆叠，相邻两级只差 1/8 半径，交叉淡化看起来
就是半径在连续变化。每一层用一个 4 停靠点的梯度 mask，精确表示
`alpha(p) = clamp(局部模糊等级 - (i-1), 0, 1)`，其中局部等级随离铰链的距离线性增加。

### 为什么在线性光空间里模糊

sRGB 空间的高斯会把白高光糊成**灰团**（亮度塌陷），看着发闷。转到线性光再模糊，
高光保持明亮并向外晕开，像真实镜头失焦。实测对比图在
`CISRGBToneCurveToLinear` → 高斯 → `CILinearToSRGBToneCurve` 前后差别很明显。

### 为什么迭代生成

高斯可叠加：`r_i` 由 `r_{i-1}` 再模糊 `sqrt(r_i² - r_{i-1}²)` 得到，每步半径都很小，
比每级从原图重新做大半径模糊快一个量级。8 级实测冷启 237ms、热启 62~108ms。

### 为什么不用 CALayer.filters

第一版用 `CALayer.filters = [CIAffineClamp, CIGaussianBlur]`，结果模糊只出现在屏幕
左下角一小块。原因是 `CIAffineClamp` 产出的是**无限延展**的 CIImage，合成器拿不到
有效边界，就把滤镜结果画到角落去了。同时 mask 的 `locations` 还被传了 `1.4` / `-0.4`
这种越界值。

现在改成在 CoreImage 里预渲染，输出矩形由 `createCGImage(out, from: scaled.extent)`
显式指定，不存在无限延展。附带三个好处：

- **可离屏验证**。`CALayer.filters` 是窗口服务器合成的，`render(in:)` 渲不出来，没法验；
  预渲染这条路可以拿测试图跑一遍存 PNG 直接看。
- **便宜得多**。模糊只在截图那一刻算一轮，不是每帧全屏高斯。
- **模糊图用 1/4 分辨率**（3024x1964 → 756x491），放大用线性插值 —— 反正已经糊了。
  8 级一共约 12MB，全分辨率要 190MB。

CoreImage 首次调用要编译 kernel，冷启约 290ms，所以启动时 `Blur.warmUp()` 在后台
先跑一次空转。生成放在 `userInitiated` 队列，不挡主线程。

梯度 mask 在铰链那头留 15% 底噪（`hingeFloor`），这样 `fold=1` 时整块屏都是虚的，
只是远端最重。隐藏后会把截图和 8 级模糊图从图层上摘掉，约 36MB 立刻还回去。

### 捕获只取一帧

`needsSnapshot` 拿到第一帧就转 CGImage 并立刻 `stop()` 停流 —— 必须拷成 CGImage，
因为 IOSurface 会被流回收。所以录屏每次合盖只跑几百毫秒，不是全程挂着。
盖板一开始动（角度 < 起始角 + 15° 且在减小）就 `prime()` 预热，避免真要显示时截图还没到。

### 虚化方向

菜单「离铰链越远越虚（只影响镜头失焦，取消=反过来）」，默认勾上。
另外两种是整屏均匀的，没有方向可言，所以这个开关对它们没作用。

### 语言

界面**默认英文**，菜单 →「Language」→「中文」切换，选择存进 UserDefaults（`language`）。
切完立刻重建菜单栏菜单，不用重启。日志固定英文。

## 原理

Apple Silicon MacBook 内置盖板角度传感器，以 HID 设备暴露：

- UsagePage `0x20` (Sensors) / Usage `0x8A`，Feature Report ID `1`
- 第 2、3 字节小端 = 角度（度）
- 实测单次读取 0.35ms，理论上限 ~2844Hz，**不需要任何系统权限**

## 从 apple.com/iphone-duo 查看器移植的原值

| 项 | 值 |
|---|---|
| 机身渐变 | `linear-gradient(160deg, #3B424E, #22272F 42%, #171B21)` |
| haze | `linear-gradient(190deg, rgba(190,205,255,.30), rgba(255,190,140,.10) 55%, transparent)` |
| haze 强度 | `opacity = .34 - .24 x 开合度` |
| 折痕 | `transparent → #fff.16 → #000.30 → #fff.14 → transparent`，`opacity = .15 + .75 x 折叠度` |
| 折痕宽度 | 机身尺寸的 `11/288` |
| 画面死区 | `0.11` —— 先开到这个比例画面才开始变，免得手一碰就晃 |
| 画面慢半拍 | 画面跟的是一根更慢的弹簧（这里用 120ms 滤波实现） |

### 刻意没有移植的

- **弹簧 + 磁铁模拟器。** 查看器里它是给鼠标拖拽造手感的。这里的输入是真实铰链，
  手感已经在你手上，再叠一层弹簧只会让画面追不上手。查看器自己也写了这点：
  「角度来自真实传感器…就必须算」。只保留 55ms 临界阻尼滤波，用来消掉
  传感器整数度数造成的台阶（1° = 1% 折叠进度，不滤会看到跳变）。
- **三机位相机混合。** 查看器需要它是因为你在用鼠标转一台虚拟手机。
  这里相机就是你的眼睛，物理上已经在动了，再叠就是双重旋转。
- **外屏 / 灵动岛 / App 网格。** 那是手机 UI，不是你的内屏。

## 构建与运行

```bash
./build.sh
open build/MacDuo.app
```

预览（不用真合盖，5 秒播一遍展平→合拢→展平）：菜单栏 →「Play Preview Once / 播放一次预览」，
或 `MACDUO_DEMO=1 ./build/MacDuo.app/Contents/MacOS/MacDuo`

停止：菜单栏 → 退出，或 `pkill -x MacDuo`

## 行为

- **起始角默认 99°**，菜单里可改成当前角度。角度 ≥ 起始角时 overlay 完全隐藏。
- **自适应采样**：静止 15Hz（0.5% CPU），一动切 125Hz（峰值约 6%）。
- **只作用于内建屏**：外接屏合盖走 clamshell，不受影响。
- 鼠标完全穿透（`ignoresMouseEvents`），不抢焦点。

## 屏幕录制权限

面板要显示真实桌面就必须用 ScreenCaptureKit，需要「系统设置 → 隐私与安全性 →
屏幕录制」里勾上 MacDuo。首次触发捕获时系统会弹授权框。

几个要注意的：

- **捕获排除了 MacDuo 自己的窗口**（`SCContentFilter(excludingApplications:)`），
  否则面板里会套着面板无限递归。
- **捕获只在 overlay 可见时开**，拿到第一帧就停流，隐藏 1.5 秒后连图层一起摘掉，
  不会 24 小时挂着录屏。画面只在本机内存里当纹理用，不落盘、不上传。
- **签名用 Developer ID，不是 ad-hoc。** 这一点很关键：ad-hoc 签名的 TCC 授权绑
  cdhash，每次重编都失效，会反复弹授权框；Developer ID 绑 Team ID，重编后权限保留。
  `build.sh` 会自动挑钥匙串里第一个 `Developer ID Application` 身份，一个都没有才退回
  ad-hoc；想指定某一个就设环境变量 `MACDUO_IDENTITY`。免费 Apple ID 没有 Developer ID，
  用 ad-hoc 也能跑，只是每次重编要重新授权一次屏幕录制。
- **授权后 macOS 会主动杀掉 App**（「退出并重新打开」那个行为），这是正常的，
  菜单里有「授权后点这里重启 MacDuo」。
- **不自动重试。** 一旦 preflight 判定无权限，本次启动只请求一次就不再问，
  避免每合一次盖弹一次窗。想重来点菜单「打开系统设置 → 屏幕录制」。

## 已知限制

1. **锁屏状态下无效。** 锁屏时 macOS 切到 loginwindow 的独立安全上下文，
   用户态 App 的窗口不参与合成。窗口层级已拉到用户态上限
   （`CGShieldingWindowLevel`），这是系统硬边界。
2. **合盖到约 40° 以下你就看不见了** —— 屏幕已转到背对你的角度，
   而休眠在 5~10° 触发。真正可见区间约为「99° → 40°」。
3. **开盖方向会慢半拍。** 开盖时 WindowServer 先做自己的淡入，
   App 才拿到角度事件，这个延迟消不掉。

## 调参

`MacDuo.swift`：

| 位置 | 含义 | 当前值 |
|---|---|---|
| `maxRadiusPx` | 最强模糊半径 | `span x sf x 0.05`（实测 98px）|
| `hingeFloor` | 铰链那头的底噪虚化量 | `0.15` |
| `Blur.levelCount` | 模糊级数，越多越平滑越慢 | `8` |
| `downscale` | 模糊图降采样倍数 | `4` |
| `startAngle` / `endAngle` | 过渡区间 | `99°` / `30°` |
| `dim` 系数 | 收尾压暗上限 | `0.35` |
| `foldDeadZone` | 开到这个比例画面才开始变 | `0.11` |
| `angleTau` | 角度平滑，越大越跟不上手 | `0.055` |
| `foldTau` | 光影慢半拍的程度 | `0.12` |
| `haze.opacity` 系数 | 内屏眩光强度 | `0.30` |
| `Blur.glassSkin` 饱和/亮度 | 玻璃板身的材质感 | `1.60` / `0.05` |
| `materialRamp` | 磨砂/玻璃的进度曲线指数，越大越缓入 | `1.35` |
| `veil` 系数 | 磨砂那层奶白的上限 | `0.26` |
| `bevelDepth` | 玻璃倒角宽度（占屏幕短边）| `0.045` |
| `bevelSqueeze` | 倒角取样指数 `S(u)=w·u^p`，越小越贴边 | `0.45` |
| `bevelSegments` | 每条边分几段逼近倒角曲线 | `4` |
| `glassOverfill` | 玻璃板比截图大出去多少（每边）| `0.025` |
